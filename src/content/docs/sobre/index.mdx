O Interop Saúde BR é uma documentação aberta sobre interoperabilidade em saúde no Brasil com HL7 FHIR. Ele reúne em um
só lugar o que um gestor precisa saber para aderir à Rede Nacional de Dados em Saúde (RNDS) e o que um desenvolvedor
precisa para produzir dados no padrão do BR Core e enviar documentos válidos à RNDS.

## Natureza do projeto

Este site é uma **proposta comunitária, independente e não oficial**. Ele não é mantido pelo Ministério da Saúde nem
pelo Departamento de Informática do SUS (DATASUS), e não substitui as publicações oficiais. Em caso de divergência,
prevalecem:

- o [BR Core](https://hl7.org.br/fhir/core/), o guia de perfis FHIR do Brasil;
- o [guia da RNDS](https://rnds-guia.saude.gov.br/) e os perfis publicados no
  [projeto da RNDS no Simplifier](https://simplifier.net/redenacionaldedadosemsaude);
- as portarias do Ministério da Saúde, citadas com link em cada página que trata de obrigações.

A intenção dos mantenedores é propor este material ao Ministério da Saúde como base para uma documentação unificada,
mantida de forma aberta. Por isso o conteúdo segue regras estritas: nenhuma obrigação regulatória é afirmada sem fonte
primária, e as páginas técnicas sempre distinguem o que vale para o BR Core do que vale para a RNDS.

### O fluxo de dados

1. O script `npm run fhir:fetch` baixa os pacotes fixados em `fhir-packages.json` (BR Core, terminologia e IPS-BR)
   dos sites dos publicadores, porque eles não estão no registro público de pacotes FHIR.
2. Os perfis da RNDS, que não são publicados como pacote, são capturados da API FHIR do Simplifier por
   `npm run fhir:vendor-rnds` e versionados no repositório, em `vendor/rnds/`.
3. O script `npm run fhir:generate` transforma os pacotes e a captura nos arquivos JSON de `src/data/generated/`, que
   alimentam as tabelas do site.
4. O script `npm run fhir:validate` valida todos os exemplos de `examples/` com o validador HL7.

### A atualização automática

O workflow
[`update-packages.yml`](https://github.com/open-health-brazil/fhir-ig/blob/main/.github/workflows/update-packages.yml)
roda toda segunda-feira às 6h (horário de Brasília) e também pode ser disparado à mão. Ele:

1. compara as versões fixadas com a versão que cada publicador marca como corrente (`current`) na sua lista de
   pacotes, e não com a versão mais alta listada;
2. só atualiza quando o tarball da nova versão está de fato disponível para download;
3. regenera os dados e abre um pull request com a lista de mudanças e os avisos do gerador.

Antes do merge, um mantenedor revisa o diff dos dados gerados, confere a validação dos exemplos, revisa as páginas
afetadas e registra a mudança no [changelog](/fhir-ig/sobre/changelog/).

A captura dos perfis da RNDS não é automática: ela é feita sob demanda, porque a RNDS não publica versões numeradas
dos seus perfis.

O BR Core 1.7.1 declara dependência da terminologia 1.2.0, que não foi publicada. O projeto usa a 1.1.0, a versão

## Licença

O conteúdo produzido por este projeto (textos, exemplos e código) é dedicado ao domínio público sob a
[CC0 1.0 Universal](https://creativecommons.org/publicdomain/zero/1.0/deed.pt-br). Você pode copiar, adaptar e
republicar sem pedir autorização, inclusive para fins comerciais e inclusive como base de uma documentação oficial.

Os artefatos de terceiros mantêm as licenças e os termos de uso dos seus publicadores:

- o BR Core, a terminologia e o IPS-BR são publicados pelos seus autores sob CC0 (campo `license` de cada pacote);
- os perfis da RNDS copiados em `vendor/rnds/` são do Ministério da Saúde e continuam sob os termos do publicador
  original, no [projeto da RNDS no Simplifier](https://simplifier.net/redenacionaldedadosemsaude). A CC0 deste
  projeto não se aplica a eles.
